# 첫 프롬프트

web_visualizer 작업을 이어받아 줘. 레포는 https://github.com/Spruce-tone/web_visualizer (main, 현재 v0.8.0) 이고, 먼저 `CLAUDE.md`, `docs/handoff/GUIDELINES.md`, `docs/objectivity.md`를 읽어.

이번 목표는 **"실제 브라우저에서 확인된 상태"를 만드는 것**이야. 지금까지 v0.6 이후 확장 화면을 실제로 열어 본 적이 없고, 댓글 찾기는 내 환경(Vivaldi)에서 안 된다고 보고된 상태야.

아래 순서로 진행하고, 각 단계가 끝날 때마다 짧게 보고해 줘. 코드를 크게 바꿔야 하면 계획부터 보여주고 내 허락을 받아.

1. **준비**: 레포를 받아 `npm install --ignore-scripts && npm run vendor && npm test`. 이 폴더를 브라우저에 압축해제 확장으로 로드해.
2. **댓글 찾기 검증 (최우선)**: YouTube 영상 하나에서 "댓글 모아서 분석" → 지도에서 원댓글 하나, 답글 하나를 눌러 "페이지에서 이 댓글 보기". 성공/실패, 걸린 시간, 버튼 아래 문구와 `[코드]`, 콘솔 오류를 기록해. 실패하면 어느 단계(page-bridge 주입 → 정렬 메뉴 찾기 → 토큰 받기 → 댓글 DOM 등장 → 강조)에서 막히는지 좁혀서 고쳐. 업데이트 전에 열려 있던 탭에서도 한 번 확인해.
3. **화면 점검**: 댓글 300개와 1,000개로 분석해서 지도 스크린샷을 찍고, 주제 수·키워드·대표 댓글이 그럴듯한지, 같은 키워드 주제가 둘로 갈리지 않는지, 걸린 시간(문구/의미/지도)을 기록해.
4. **의미 모델 확인**: 모델 선택 "자동"이 어떤 모델·장치(GPU/CPU, 멀티스레드 여부)로 도는지, 첫 다운로드 크기와 시간을 기록해.
5. 1~4의 결과로 **문제 목록과 고칠 순서**를 제안해 줘. 구현은 내가 순서를 확인한 뒤에 시작해.

지켜야 할 것: 데이터 저장 금지, 의심 점수에 어조·주장·대상 넣지 않기, "조작" 판정 문구 금지, 원격 코드 로드 금지. 보고할 때는 **바뀐 것 / 실제로 확인한 것 / 확인 못 한 것 / 내가 할 일**을 나눠서 한국어로 써 줘.
